# Yodoku — Bug & Risk Audit (2026-08-22)

**Scope:** READ-ONLY audit of `YODOKUAPP` (React 19 + TS + Vite 7 + Tailwind 4 + Framer Motion SPA, deployed to Vercel at yodoku.app). 6 games incl. the new Quiz Master (`/quiz`).
**Method:** Every finding below was verified against the actual files (`read_file` / `cat -n` / runtime `node` checks). No files were modified. Line numbers reflect the working tree at audit time (note: the tree was actively being edited mid-audit — see "Repo state" note).

> ⚠️ **Repo-state note (important):** `git status` shows an uncommitted work-in-progress — the quiz is being expanded from 7 → 11 categories. Source category files (`scripts/quiz-bank/{technology,food,art,animals}.json`) are present and valid but **untracked**, `scripts/merge-quiz-bank.mjs`, `quizLogic.ts`, `Hub.tsx`, `QuizHome.tsx`, `QuizAbout.tsx`, `FermiPage.tsx`, `OrderlePage.tsx` are **modified but uncommitted**, and `public/data/quiz-bank.json` is **still the old 7-category build**. This mismatch is itself a finding (B2).

## MUST FIX BEFORE NEXT DEPLOY

1. **FERMI — the "Absolute zero temperature?" puzzle is unwinnable.** `puzzleGenerator.ts:139` has `answer: -273.15`, but `FermiPage.tsx:51` rejects every guess `v <= 0` ("Enter a positive number."). The correct answer can never be submitted, so that day's daily puzzle is impossible to solve. The log-scale chart also breaks (`FermiPage.tsx:107-109` computes `Math.log10(-273.15)` → `NaN` → `left: NaN%` markers). **Fix:** either change the answer to a positive form (e.g. `273.15` with units "°C below zero") or allow negative input for this puzzle. (CRITICAL, B1)
2. **Quiz bank is out of sync with UI copy — do NOT deploy the current copy change without regenerating the bank.** UI now claims **11 categories** (`quizLogic.ts:35-47`, `Hub.tsx:343`, `QuizHome.tsx:45`, `QuizAbout.tsx:23`) but the deployed `public/data/quiz-bank.json` still has only **7 categories / 420 questions**. Until `node scripts/merge-quiz-bank.mjs` is run and the regenerated `quiz-bank.json` is committed/deployed, the About/Home pages advertise 4 categories (technology/food/art/animals) that can never appear in a quiz. (HIGH, B2)
3. **`public/sw.js` is invalid JavaScript and the service worker never registers.** It contains TypeScript syntax (`(e: any)` at `sw.js:5`, `(self as any)` at `sw.js:9` & `:18`) in a `public/` file that is served verbatim (Vite does not transpile `public/`). The browser throws a parse error, `register()` rejects, and `index.html:11` has no `.catch()` → an unhandled promise rejection on every page load. Offline/PWA support is silently dead. (HIGH, B3)

## Bug Register

### B1 — FERMI "Absolute zero" puzzle is unwinnable (CRITICAL)
- **Evidence:** `src/pages/FermiPage.tsx:51` — `if (!isFinite(v) || v <= 0) { setError('Enter a positive number.'); return; }`; `src/utils/puzzleGenerator.ts:139` — `answer:-273.15`.
- **Effect:** The one daily puzzle whose correct answer is negative can never be answered correctly. It also poisons the chart (`Math.log10(-273.15)` = `NaN`, `FermiPage.tsx:107-109`).
- **Why it shipped:** `validateFermiPuzzle` (`puzzleGenerator.ts:189`) *does* catch `answer <= 0`, but `validateAll()` (`puzzleGenerator.ts:196`) is never invoked at runtime (dead validation).
- **Fix:** Change answer to positive representation (e.g. `273.15` + units "°C below zero") or allow negative input. Add a pre-build data validation step that runs `validateAll()`.

### B2 — Quiz bank (7 categories) out of sync with UI copy (11 categories) (HIGH)
- **Evidence:** `src/utils/quizLogic.ts:35-47` (`CATEGORY_META` has 11 entries); `src/pages/Hub.tsx:343` ("…eleven categories"); `src/pages/QuizHome.tsx:45` ("Eleven categories"); `src/pages/QuizAbout.tsx:23` ("span eleven"); vs `public/data/quiz-bank.json` = 7 categories, 420 questions (verified via `node`: categories `general,sports,movies,geography,science,history,music`).
- **Effect:** Marketing/About copy is false; 4 categories of shipped source content are unreachable. If the copy lands without the regenerated bank, the "eleven categories" claim is a live lie.
- **Fix:** Run `node scripts/merge-quiz-bank.mjs` (all 11 source files now exist and are valid — 60 qs each, 0 bad answers/options, all IDs unique) and commit the regenerated `quiz-bank.json` in the same deploy as the copy change. Add a CI/check that asserts `CATEGORY_META` keys == bank categories.

### B3 — `sw.js` is syntactically invalid JS; service worker never registers (HIGH)
- **Evidence:** `public/sw.js:5` `(e: any)`, `:9` and `:18` `(self as any)` — TypeScript type syntax in a `.js` file served raw from `public/`; registered via `index.html:11` with no `.catch()`.
- **Effect:** SW fails to parse → offline/PWA silently broken + unhandled rejection each load.
- **Secondary risk (if the syntax is fixed):** the fetch handler is **cache-first** with a static cache name `yodoku-v1` (`sw.js:2`, `:21-33`). It would cache `/data/quiz-bank.json` and `/index.html` and serve them stale forever — breaking the weekly question-bank updates and (worse) serving an old `index.html` with hashed JS/CSS chunk names that 404 after a redeploy.
- **Fix:** Rewrite in plain JS (strip type annotations), use a **network-first** strategy for HTML and for `/data/*.json`, and bump the cache name on deploy (or drop the SW entirely — it adds risk without much benefit for a serverless daily game).

### B4 — `buildDailyQuiz` can emit duplicate questions (~6 days/year) (MEDIUM)
- **Evidence:** `src/utils/quizLogic.ts:79-91` — the pick loop never removes a chosen question from its pool; only category diversity is tracked, not question identity.
- **Verified:** a 365-day simulation of the real logic (420-q bank) found **6 days with a duplicated question** in the 10-question set (e.g. `2026-11-03`, `2027-02-01`, `2027-03-15`, `2027-04-28`, `2027-05-04`).
- **Effect:** On those days a player sees the same question twice (and only 9 unique questions). Also means `scripts/test-quiz-logic.mjs:82` (`ids.size !== 10` throws) would fail when the weekly curator runs it on such a date.
- **Fix:** Track picked question IDs (or `splice` from the pool) in `buildDailyQuiz`.

### B5 — "Same questions for everyone / shared score" is false across timezones (MEDIUM)
- **Evidence:** `src/utils/dailySeed.ts:28-34` (`getTodayDateStr` uses **local** date) vs `src/utils/quizLogic.ts:52-57` (`getQuizNumber` diffs **UTC** days). Copy: `src/pages/QuizHome.tsx:126` ("Same questions for everyone, every day"), `src/pages/QuizAbout.tsx:21-23`.
- **Effect:** At the same instant, players in different timezones see different "today" date strings → different seeded quiz → cannot compare scores. Inherent to local-midnight daily games (Wordle-style), so treat as a copy-expectation issue, not a code bug. (Streak logic itself is consistent — see "Verified correct" below.)
- **Fix:** Either soften the copy ("same questions for everyone *in your timezone*") or switch the quiz to a single UTC rollover (would surprise users in ±12h zones).

### B6 — Change-by-One daily challenge fetch has no error handling (MEDIUM)
- **Evidence:** `src/utils/cbo-dailyChallenge.ts:66-67` — `fetch(pairFiles[len]).then(r => r.json())` with no `res.ok` check and no `try/catch`; `:71-72` — `pairs[idx]` is dereferenced with no guard.
- **Effect:** A failed/404 pair file rejects the whole `Promise.all` (unhandled), and an empty pair file makes `pairs[NaN]` → `undefined` → crash on `pair.start_word`.

### B7 — WordPoolPage fetch has no `.catch` (MEDIUM, carried over from INSPECTION_REPORT #13)
- **Evidence:** `src/pages/WordPoolPage.tsx:143` — `fetch('/data/wordpool-categories.json')`; no `.catch` anywhere in the file (grep-verified).
- **Effect:** On network/JSON failure the page stays in a loading state forever with no retry/error UI.

### B8 — Quiz replay overwrites the stored result despite "one attempt / no score change" copy (MEDIUM)
- **Evidence:** `src/pages/QuizPage.tsx:92-97` (`handleReplay` resets answers and allows re-answering) → `:67-72` (`finish` → `saveQuizDone(date, finalAnswers)` overwrites the saved answers/score). Copy: `QuizPage.tsx:212` ("Replay (no score change)"), `QuizAbout.tsx:60` ("one attempt that counts per day").
- **Effect:** The stored "done" record reflects the *last* replay, not the first attempt. Only the streak is protected from double-count (`bumpStreak` is idempotent, `quizStorage.ts:51`). Low real-world impact (no server/leaderboard), but the copy over-promises.

### B9 — ComingSoon page stale + orphaned route (LOW)
- **Evidence:** `src/pages/ComingSoon.tsx:9` — "A fourth game is in the works." (there are 6 games); route still registered at `src/App.tsx:59` but no Hub link points to it.
- **Fix:** Delete the page + route, or repurpose the copy.

### B10 — `manifest.json` stale copy (LOW)
- **Evidence:** `public/manifest.json:4` — "Five daily word and logic puzzles — free, no ads, no tracking."
- **Reality:** 6 games; an ad layer exists (`src/utils/ads.ts`, `src/components/AdSlot.tsx`); Vercel Analytics (`src/App.tsx:54`) does track. "no ads" / "no tracking" will contradict the marketing/ad plan once Monetag is enabled.

### B11 — `index.html` theme-color mismatch + duplicate manifest link (LOW)
- **Evidence:** `index.html:33` `theme-color "#0f0f1a"` (dark) vs the paper background `#f6f3ec` (`index.css:1180`); duplicate `<link rel="manifest">` at `index.html:6` and `:34`.

### B12 — Dead / stale code (LOW)
- `src/utils/quizLogic.ts:129-131` `getTodayDateStrLocal` — unused.
- `src/utils/cbo-gameLogic.ts:88-109` `suggestNextStep` — unused (hints use BFS `calculateOptimalPath`, verified in `ChangeByOnePage.tsx:15,372`).
- `src/utils/puzzleGenerator.ts:150,168,196` `generateOrderleForDate` / `generateFermiForDate` / `validateAll` — the "weekly rotation schedule" is dead; `OrderlePage.tsx:16-21` and `FermiPage.tsx:17-22` use a simple linear `daysSinceLaunch % BANK.length` rotation instead, ignoring the Monday-cooking/Tuesday-science schedule documented in the comments.

### B13 — `showRewardedAd` is a fail-open stub (LOW, latent footgun)
- **Evidence:** `src/utils/ads.ts:27-29` — returns `{ rewarded: true, dismissed: false }` without showing anything.
- **Effect:** Harmless today (no caller, `shouldShowAdForHint` returns false so hints are free), but if a hint-gating path is wired to it later, users get unlimited free rewards with no ad.

### B14 — `AdSlot` `slot` prop is not wired to any ad-network zone (LOW)
- **Evidence:** `src/components/AdSlot.tsx:31-41` renders `<div data-ad-slot={slot}>`; `AD_CONFIG` (`ads.ts:10-13`) has only `monetagTagUrl` / `adsenseClient` with no zone-id map. Monetag tags don't target arbitrary `data-ad-slot` divs automatically.
- **Effect:** Even after pasting a Monetag URL, ad impressions may not appear at the named slots without a zone mapping. Ad layer is effectively a stub (ads are disabled until `monetagTagUrl` is filled).

### B15 — Hub ORDERLE description says "six items" (LOW)
- **Evidence:** `src/pages/Hub.tsx:313` — "Put six items in the correct order"; actual ORDERLE puzzles have 4–8 items (`puzzleGenerator.ts:64` has 5, `:68` has 4, `:88` has 8, `:90` has 7, `:91` has 8, `:97` has 8).

### B16 — ORDERLE practice-mode share always reports puzzle #0 (LOW)
- **Evidence:** `src/pages/OrderlePage.tsx:86` — `const idx = practice ? 0 : getTodayIndex();` while the practice puzzle index is random (`:33`).
- **Effect:** Practice share text shows `ORDERLE #0` regardless of the puzzle actually played.

### B17 — Duplicate/overridden `:root` blocks + large dead CSS (LOW)
- **Evidence:** `src/index.css` defines multiple competing `:root` blocks (grey theme `:16-37`; old "Retro Keyboard Plate" hub `:64-73` with `--hub-bg:#E8E5E1`; Sticker Pack hub `:1179-1193` with `--hub-bg:#f6f3ec`). The Sticker Pack block wins only because it comes last. Entire dead class families (`.hub-*`, `.game-home-*`, old `.lettermix-*`, `.cbo-*`, `.wp-*`) remain for UI that now uses inline styles + CSS vars.
- **Effect:** No functional bug, but a maintenance hazard (two competing hub palettes) and ~30KB of dead CSS.

### B18 — Quiz page left open across local midnight resets mid-game (LOW)
- **Evidence:** `src/pages/QuizPage.tsx:31` recomputes `const date = getTodayDateStr()` every render; the load effect depends on `[date]` (`:65`), so at midnight the quiz refetches/rebuilds and drops in-progress answers.

### B19 — sitemap/robots use non-www domain while site redirects to www (LOW)
- **Evidence:** `public/robots.txt:4` and `public/sitemap.xml:3-10` reference `https://yodoku.app/…`; the domain redirects to `www.yodoku.app`. Minor SEO canonicalization inconsistency.

## Verified correct (checked, no bug found)

- **Streak `yesterdayOf` across month/year/DST boundaries** (`quizStorage.ts:29-33`): uses local noon + `setDate(-1)`, so `2026-01-01→2025-12-31`, `2026-03-01→2026-02-28`, leap years, and DST all resolve correctly. **No bug.**
- **localStorage corruption handling** (`quizStorage.ts:11-58`): all reads wrapped in try/catch with safe defaults. Minor note: `getQuizDone` casts without validating that `answers` is an array (`:14`), so a corrupted-but-parseable `answers` string would flow into `.slice()` (`QuizPage.tsx:52`) and later never match — degraded but not crashy.
- **Answer-index integrity** (`merge-quiz-bank.mjs:41-48`, `quizLogic.ts:99-103`): merge script enforces `answer ∈ [0,3]` and `options.length === 4`; `buildDailyQuiz` remaps the answer index after option shuffle correctly. Runtime check of the 420-q bank found **0 bad answer indices / 0 bad option counts / 0 duplicate IDs**.
- **Determinism** of `buildDailyQuiz`: same date → identical output (verified by running the test-logic replica twice).
- **XSS / injection:** No `dangerouslySetInnerHTML` anywhere. The only `innerHTML` writes are `= ""` clears (`AnimatedString.tsx:147`, `LetterMixBackgroundGrid.tsx:44`). All quiz text (`question`, `options`, `hint`, category labels) is rendered as React text nodes (auto-escaped). External quiz data is **safe** to render as-is.
- **Routing/SPA fallback:** `vercel.json` rewrites `/(.*)` → `/index.html` and `public/_redirects` has `/* /index.html 200`; direct nav to `/quiz/play`, `/quiz/about`, and all game routes resolves to the SPA. `App.tsx` has a `*` → `NotFound` catch-all (`:116`). **No 404 issue.**
